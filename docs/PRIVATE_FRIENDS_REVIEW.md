# Private friend connections

A signed-in user can explicitly select an alias and interests, create a private expiring link, and send it manually. The authenticated recipient submits their own selected projection. Claiming is pending, not friendship: the sender verifies the claimant's account ID through a trusted channel and confirms. Each person can update only their shared interests, block, export or remove the connection. Individual discovery remains account-free. No simulated participant actions exist in this screen.

Files: `friends-core.js` validates projections/records; `friends-client.js` sends scoped RPCs; `friends-view.js` handles invitations/privacy; `friends-runtime.js` lazy-loads the gated route and shares the existing Auth client. `social-request.js` extracts the existing authenticated request boundary so Plans and Friends share safe errors/timeouts without duplicating transport logic. Both rendered Friends and Plans bind each request to the displayed session actor; no actor ID is sent as RPC authority. Existing Plan transport and privacy tests protect the extraction.

`supabase/social-friends.sql` is additive after `social-plans.sql`, idempotent and review-only. RLS is enabled and raw table privileges revoked; all access uses participant-checked RPCs. Invite hashes never enter reads. Two-way blocks use the existing social block table, separately from Workspace roles/business reports. Deleting either participant’s Auth account cascades connection records. Blocked/expired participation can still be removed or exported with other-person content redacted.

Validation commands: `npm test`, `npm run lint`, `npm run build`, `npm run test:browser`, `npm run test:plans:configured`, `npm run test:friends:configured`, `bash scripts/check-workspace-reporting.sh`, `npm run test:social-sql`, `npm run test:social-recovery`. The social SQL gate also tests friend claim concurrency and scoped friend data backup/restore. Its Docker database has no network/ports, ignores hosted connection strings and is removed after testing. Auth, blocks and plan tables are preserved in place during the friend restore test; this is not full-provider disaster recovery.

All backend browser traffic in enabled-bundle tests is intercepted and synthetic. The default app keeps `VITE_PRIVATE_FRIENDS_ENABLED=false`. No external infrastructure, real accounts or social data is activated. PR #24's already-approved staging remains tied to its exact documented commit; installing this additional schema or using real participants requires a separately reviewed scope. The still-missing project/credentials for that earlier approval remain documented in `STAGING_PROJECT_SETUP.md`.

Remaining: authenticated shared shortlists and plans from a confirmed friend, in-app notifications, stronger abuse rate controls/retention operations, full hosted Auth/privacy/recovery verification, physical devices, and an authorized real-user pilot. There is no public directory, verified identity badge, location collection or automatic contact delivery. Forwarded invite links are capabilities; inviter confirmation helps detect an unexpected claimant but is not identity verification.

Preserve Auth, blocks, plans and unrelated schemas. No rollback has been run against a hosted project.
