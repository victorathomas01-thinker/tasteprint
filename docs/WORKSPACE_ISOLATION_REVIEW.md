# Workspace account isolation and genuine backend verification

Workspace previously awaited database work inside its Auth callback and loaded team data without account/team generations. The SDK callback can hold its session lock, and late responses could restore an old account's team or invitation display.

Auth callbacks now return synchronously, clear old team data and private tab titles immediately on actor changes, and schedule authenticated loading after the callback. Same-account token refresh preserves the current form. Initial recovery cannot replace newer Auth events. All Workspace REST/RPC actions capture the initiating actor and generation, check fresh session identity and use that captured bearer token. Late old-account/team responses cannot update state. Serialized controls prevent duplicate mutations; sign-out remains available during requests. An inaccessible explicitly requested team is unavailable, rather than silently selecting another accessible team. The public capability helper does not inherit the demo owner's permissions in connected mode.

This is not server rollback: a request accepted before logout may finish under its original valid actor. The application refuses to display its late result under another account. RLS remains the backend authority.

Genuine local testing also exposed two existing database assumptions hidden by earlier fixtures:

- Crypto functions were resolved only through public; managed Supabase normally installs pgcrypto in extensions. Affected Workspace/member/lifecycle and anonymous owner-token-erasure functions now include both trusted namespaces and put pg_temp last. The reporting runner installs pgcrypto in extensions so reapplication, invitations, member references, ownership and owner-token erasure exercise the managed layout.
- Campaign draft table privileges relied on platform defaults. The source now explicitly grants authenticated SELECT/INSERT/UPDATE/DELETE, with the existing tenant/role RLS policies unchanged. Positive editor read/write and viewer/nonmember/cross-tenant denial are tested, avoiding a false green where all access simply lacked grants.

No new tables or external migrations. Existing ordered source reapplication is required before a future approved hosted test: schema.sql, campaigns.sql, campaign-registry.sql, workspaces.sql, workspace-member-refs.sql, workspace-lifecycle.sql, workspace-reporting.sql. Reapply the complete order so scoped member references and restrictive reporting grants remain in effect.
