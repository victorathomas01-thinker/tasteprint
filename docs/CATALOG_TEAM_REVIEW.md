# Authenticated catalog contribution and review

The existing local workbench now links to an optional connected team queue. Authors transfer a deliberately selected local draft, submit it, receive independent review and then have a publisher release the approved version to a paginated public API. Copying a team entry back for structured editing preserves existing local work unless replacement is explicitly confirmed. Review notes survive same-version UI validation; a changed version resets consent. Missing/stale source checks get a clear correction message rather than a generic failed approval. No framework or dependency was added.

The feature defaults off. Signup/company ownership do not confer catalog permissions. `supabase/catalog-contributors.sql` is additive review-only code and is outside PR #24’s hosted approval. Roles are assigned by the founder using approved database administration, not by the browser. The distinct roles are contributor, reviewer, publisher and admin; even an admin cannot approve/publish their own authored entry. The original local workbench, six modules, Passport, company demos and private social features remain available.

All raw role/entry/history access is revoked and tables use RLS. Scoped security-definer RPCs enforce actor ownership, current roles, exact team version, strict JSON metadata and manual source freshness. Source keys deduplicate normalized HTTPS host/default port/trailing slash, sorted query parameters and known tracking/fragment variants. This is conservative normalization, not semantic website identity or a web crawler. No source is fetched automatically. Editing resets review/publication. Withdrawal/removal and stale checks exclude content from public reads. Public projections omit drafts, histories, account IDs and internal notes. Team history omits account IDs; explicit deletion cascades history.

Author deletion removes authored records/history. Reviewer identity deletion makes its approval unavailable to public reads. Role removal prevents subsequent actions; it does not invalidate previously authorized editorial decisions. Founder database privileges still require careful staging/production separation and are not exposed to contributors. Catalog roles grant no extra access to private Passport, friend, plan or Workspace information.

Validation covers strict client state/role/route/actor boundaries, public build gates, PostgreSQL grants/ownership/role separation/self-approval/stale version/source validation/deduplication/history/withdrawal, and browser disabled routes, local preservation, injection, role controls, consent reset, missing source check, outage and late logout. The genuine loopback-only Auth/PostgREST/PostgreSQL build now exercises three separate browser accounts moving from structured local editing through independent review and publication, plus direct API denial/readback. A scoped entries/history archive additionally verifies atomic duplicate-restore failure, exact restored rows and preserved friend data/role access. It also verifies revocation and durable logout after reload. Test sessions are seeded once per browser context so navigation cannot silently reauthenticate a signed-out account.

Changed components: catalog-team-{client,view,runtime}.js, review-only catalog schema, local workbench link, scoped dark styling, route/privacy/public-build guards and their Node/SQL/browser/genuine-stack runners. No hosted schema, role, public listing, infrastructure or real-data collection was activated. Only disposable local synthetic records were published during testing.

The public catalog API is ready for consumer integration; Discover/Together still use the bundled reference catalog in this milestone. CSV bulk preparation remains local with explicit per-entry team upload. Queue/history over 2,000 rows require pagination; local and author caps are documented in CATALOG_CONTRIBUTOR_GUIDE.md. Maintained real content, source rights, provider recovery, hosted setup, real devices and pilot evidence remain outstanding. This does not confer company verification or claim launch readiness.
