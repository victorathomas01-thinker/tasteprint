# Catalog workbench and contribution process

Open Business tools → Open catalog workbench (`?catalogAdmin=1`) in the local review build. This tool stores drafts on this browser, not a server. It reads no private Passport, plan, account or company data. It does not establish an authenticated contributor role or publish content. Contributors should use only public listing information; development validation uses synthetic fixtures.

1. Create a listing or open Bulk import and exports. Download the CSV template, or import the standard catalog JSON array. CSV supports quoted commas/newlines, pipe-separated known interest tags and optional metadata. Blank cost/access/availability means unknown, never free/accessible/available. Numeric fields must be nonnegative. Use ISO timestamps for source checks/expiry.
2. Include a canonical HTTPS source, publisher and short source/reuse note. Review rights, freshness, suitability, practical constraints and the action link. A generic website is not an authorized data API. Do not scrape reviews/images, invent offerings, or copy personal information.
3. Save the draft. Updates keep the ID/source and increase the revision; editing resets approval. Batch imports are atomic: one invalid, duplicate or stale-revision row rejects the whole batch. CSV revisions are explicit; structured editing increments them automatically.
4. Enter a review note and Submit for review. Manually check the source and enter the actual check timestamp before approval. Dates are never generated as evidence. Return to draft for corrections or Withdraw when inaccurate. History retains saved snapshots and review notes; caps are 200 entries and 100 history events per entry, with explicit errors instead of dropping history.
5. Export approved catalog for review. Only active, approved entries checked within 30 days are included. **This download does not publish.** Submit it for a development code review and synthetic tests before any catalog integration. Real publication and contributor permissions need the authenticated ownership/reviewer implementation; no local flag can provide that trust.
6. Export draft items JSON for lossless interchange and workbench history/raw backup for records. CSV is a flat subset and prefixes formula-like cells for safe spreadsheet opening; use JSON to preserve exact text and preference attributes. Local storage can be cleared by a browser; exports are manual backups. There is no automatic recovery/sync promise.

Storage failures preserve the current form and report failure. Unreadable/newer local state locks edits until you download the raw backup and explicitly confirm Reset local workbench. Reset only removes this workbench's key; Passport, company drafts, campaigns and plans are unaffected. No automatic scheduled cleanup is installed.

Files: `catalog-editor-core.js` handles import, review, history and storage; `catalog-editor.js` is the structured UI; `catalog-core.js` remains the shared data/ranking contract. `scripts/check-catalog-editor.js` and `check-catalog-editor-browser.js` cover atomic imports, transitions, staleness, safe rendering/downloads, corrupt storage and nonpublication. `npm run lint` adds a dependency-free JavaScript syntax check; it is not a style/TypeScript audit.

Authenticated contributor/approver roles, server-side review enforcement, production publishing, hosted audit histories and maintained real restaurant/event sources remain outstanding. The local workbench deliberately makes no claims about them.
