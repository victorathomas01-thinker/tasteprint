# Catalog workbench and contribution process

Open Business tools → Open catalog workbench (`?catalogAdmin=1`) in the local review build. This tool stores drafts on this browser, not a server. It reads no private Passport, plan, account or company data. It does not establish an authenticated contributor role or publish content. Contributors should use only public listing information; development validation uses synthetic fixtures.

1. Create a listing or open Bulk import and exports. Download the CSV template, or import the standard catalog JSON array. CSV supports quoted commas/newlines, pipe-separated known interest tags and optional metadata. Blank cost/access/availability means unknown, never free/accessible/available. Numeric fields must be nonnegative. Use ISO timestamps for source checks/expiry.
2. Include a canonical HTTPS source, publisher and short source/reuse note. Review rights, freshness, suitability, practical constraints and the action link. A generic website is not an authorized data API. Do not scrape reviews/images, invent offerings, or copy personal information.
3. Save the draft. Updates keep the ID/source and increase the revision; editing resets approval. Batch imports are atomic: one invalid, duplicate or stale-revision row rejects the whole batch. CSV revisions are explicit; structured editing increments them automatically.
4. Enter a review note and Submit for review. Manually check the source and enter the actual check timestamp before approval. Dates are never generated as evidence. Return to draft for corrections or Withdraw when inaccurate. History retains saved snapshots and review notes; caps are 200 entries and 100 history events per entry, with explicit errors instead of dropping history.
5. Export approved catalog for review. Only active, approved entries checked within 30 days are included. **This download does not publish.** Submit it for a development code review and synthetic tests before any catalog integration. The separate connected review workflow below enforces ownership and roles on the server; local approval alone cannot provide that trust.
6. Export draft items JSON for lossless interchange and workbench history/raw backup for records. CSV is a flat subset and prefixes formula-like cells for safe spreadsheet opening; use JSON to preserve exact text and preference attributes. Local storage can be cleared by a browser; exports are manual backups. There is no automatic recovery/sync promise.

Storage failures preserve the current form and report failure. Unreadable/newer local state locks edits until you download the raw backup and explicitly confirm Reset local workbench. Reset only removes this workbench's key; Passport, company drafts, campaigns and plans are unaffected. No automatic scheduled cleanup is installed.

Files: `catalog-editor-core.js` handles import, review, history and storage; `catalog-editor.js` is the structured UI; `catalog-core.js` remains the shared data/ranking contract. `scripts/check-catalog-editor.js` and `check-catalog-editor-browser.js` cover atomic imports, transitions, staleness, safe rendering/downloads, corrupt storage and nonpublication. `npm run lint` adds a dependency-free JavaScript syntax check; it is not a style/TypeScript audit.

## Connected team review (development branch, default off)

Open **Open connected catalog review** from the local workbench (`?catalogTeam=1`). This requires a separately approved configured backend, the review-only `supabase/catalog-contributors.sql` schema, `VITE_CATALOG_TEAM_ENABLED=true`, an account and an explicitly assigned catalog role. This is outside PR #24’s hosted approval. No hosted project or role has been activated here.

1. The founder assigns staging-only account UUIDs one of contributor, reviewer, publisher or admin through the approved database administration process. No account receives a role by signing up, owning a company or editing local storage. The application contains no role-escalation RPC or email/user directory. Never grant database or production administration to a content contributor.
2. Prepare a public listing in the structured local workbench or CSV import. Enter the actual source-check timestamp after a manual check. Leave unknown price, access and availability unknown. In connected review, choose **Local listing draft**, confirm its public fields and **Send selected draft to team**. Upload is explicit, one listing at a time. Your local work is kept.
3. Review the team version and **Submit for review**. Authors see their own drafts; reviewers see the submitted queue. A separate reviewer checks the source and full metadata, adds a note, confirms the exact version and approves or returns it. Even admins cannot approve their own work. Missing/stale source checks must be corrected in a new author draft.
4. A publisher reviews the approved version, explicitly confirms public release and chooses **Publish reviewed listing**. Reviewers alone cannot publish; authors cannot publish their own entry. This makes the item readable through that configured backend’s paginated public catalog API. Consumer Discover/Together do not yet fetch this API; that integration is a separate milestone. No real publication was performed by these development tests.
5. To edit your team entry, **Copy to local workbench for editing**, then edit the structured form. Replacing an existing local draft requires a backup confirmation. Sending the newer revision resets approval and removes the previous public version until review/publication is completed again. Stale team versions fail instead of overwriting another change. Refresh and inspect before retrying an uncertain save.
6. Authors or authorized reviewers/publishers can withdraw with a reason. Withdrawn/stale listings disappear from public reads. Authors can permanently remove their own draft or withdrawn entry and its history after explicit confirmation. Export listing history before removal if needed. Public reads exclude histories, notes and account IDs; team history exports omit account IDs.

Roles grant no extra Passport, friend, plan or business-data access. Removing a role blocks the next team request; it does not erase previously authorized editorial decisions. Account deletion erases authored entries/history and removes the account’s review references. Such publications are then unavailable. Keep source maintenance and copyright/reuse review separate from company verification or paid partnership.

Current limits: 200 local drafts/100 local history events per entry; 500 team entries per author; team queue/history over 2,000 entries fail explicitly until pagination is added. Public API pages contain at most 100 items and use a last-ID cursor. Public source checks expire after 30 days; no maintenance job or contributor account onboarding email was activated. Real content maintenance, hosted activation, consumer API integration and production operations remain outstanding. See CATALOG_TEAM_REVIEW.md for evidence.
